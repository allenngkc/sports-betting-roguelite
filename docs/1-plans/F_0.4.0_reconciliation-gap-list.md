## 2. What breaks — market-owned defects

### M-01 · Duplicate anytime-scorer offers — **high, player-facing** · FIXED

> **Correction (2026-07-31, same day):** the rates first published in this section
> were measured per *roster* and understated the defect. The scorer board is one flat
> list spanning **both** rosters (`MatchModel.BuildOffers:99-102`), rendered with no
> team label (`SportsbookApp.cs:343-352`), so the true collision space is all 14 board
> rows in a matchup. Corrected figures below.

`SlateGenerator.MakeRoster` (`engine/SlateGenerator.cs:99-112`) draws each player
name as two independent uniform picks from a 12×12 pool (`:94-97`, `:109`) — with
replacement, no dedupe. Two players on the same scorer board can carry the identical
name.

Measured over 5,000 generated slates at shipped config (`PlayersPerTeam=7` → a
14-row board, `MatchupsPerSlate=6`):

| Metric | Rate |
|---|---|
| **Slates** with ≥1 duplicated board name | **98.08%** (4904/5000) |
| **Matchups** with ≥1 duplicated board name | **48.55%** (14564/30000) |
| …duplicate pair **also shares a role** | **17.61%** (5283/30000) |
| …duplicate spans **both teams** | 29.27% (8782/30000) |
| Max distinct duplicated names in one matchup | 5 |

The PLAYERS tab labels each offer `"{NAME} [{ROLE}]"` (`SportsbookApp.cs:350`) with
no team attribution, so in the same-role case the two offer rows are **byte-identical
apart from price**. First probe seed reproduces it — note four separate `GUS`es and an
exact duplicate at rows 5/6:

```
REPRO seed=PROBE-0 matchup=1  (Moose Jaw Middlemen v San Francisco Meatballs)
   row  5: GUS RACKET [DF]
   row  6: GUS RACKET [DF]
   row  7: GUS GASKET [FW]
   row  9: GUS CINDER [FW]
   row 10: GUS LANYARD [MF]
```

Grading is identity-based (`MatchModel.cs:230`, `ReferenceEquals`), so settlement is
*correct* — which makes this worse, not better: the player can back one GUS RACKET,
watch the other one score, and be told they lost with no way to tell the rows apart.
`Leg.DisplayLabel` (`MatchModel.cs:250`) collapses identically in the ledger, so the
receipt cannot disambiguate it either.

Precedent for the fix was already in the file: team nouns are explicitly deduped
within a slate — *"Unique noun per team keeps names distinct within a slate"*
(`SlateGenerator.cs:34`). Player names were missed.

**RESOLVED** (`engine/SlateGenerator.cs`). Both rosters of a matchup already draw
from one shared stream (`:45-50`, `hub.DeriveMatch(round, i, "roster")`), so a single
`HashSet<string>` threaded through both `MakeRoster` calls now rejection-resamples any
colliding name on that same stream. Board-wide uniqueness, replay-exact.

Pricing is unmoved **by mechanism, not by assertion**: `PlayerRole` and
`ScoringWeight` are index-derived (`:106-108`) and untouched by the fix, and
`MatchModel.TrueProbability` never reads `Player.Name` — so every scorer price is
bit-identical. Pinned by `engine.tests/RosterNameTests.cs`
(`Anytime_scorer_pricing_is_unaffected_by_player_names`).

Evidence: duplicate rate **48.55% → 0.00%** over the same 30,000 matchups; engine
suite **160 → 164, all green**; `GoldenSeedTests` untouched and passing (seed
GOLDEN-W2 bank pin 452.559054816409 held). A guard now throws naming `PlayersPerTeam`
if the dial is raised past the 144-combination pool.

### M-02 · Public grading overload throws on scorer legs — **medium, API trap**

`MatchModel.Grades(MatchStatLine, MarketSelection)` (`MatchModel.cs:200`) is public
and throws `ArgumentException` for `MarketKind.AnytimeScorer` (`:214-215`). Only the
3-arg roster-aware overload (`:221`) is safe. No test covers the throw, and nothing
prevents a caller from picking the wrong overload.

**Action:** restrict the 2-arg overload's visibility (or route it through the safe
overload), and add the missing test.

### M-03 · The balance gates do not cover the expansion — **high, process**

G1–G6 all pass, but the per-market exposure table shows what the bots actually bet:

| Strategy | markets actually exercised |
|---|---|
| skilled | Moneyline 72.7%, Total Goals 27.3% — **BTTS / Corners / Cards / Scorer: 0 legs** |
| naive, noshop, martyr | Moneyline 100% |
| random | ML, Goals, BTTS, Corners, Cards — **Scorer: 0 legs** |

Anytime Scorer is excluded from every bot by design (`sim/RandomStrategy.cs:92-96`,
`sim/SkilledStrategy.cs:157`; `SkilledStrategy.Opposite` `:562-570` throws
`"Bots do not price {Kind}"`).

So **"ALL GATES PASS — the economy holds" currently certifies a two-market game.**
G2–G6 all depend on the skilled bot, and the skilled bot never touches four of the
six markets F_0.4.0 shipped. Nothing in the gate campaign would detect a mispriced
corners, cards, BTTS, or scorer market.

This is the single highest-value follow-up for this seat. It is a coverage gap, not
a proven balance problem — see F-01.

**Action:** extend skilled-bot market coverage, or add a market-coverage gate that
fails when a shipped `MarketKind` records zero skilled legs. Scorer pricing needs a
bot-independent EV harness since bots are policy-excluded from it.

## 3. Falsified — do not re-run

### F-01 · Corners is **not** mispriced

At `--runs 1000`, Total Corners showed `mean leg EV +0.6pp` for the *random* bot —
an uninformed selector cannot beat the vig, so this read as mispricing. Re-measured
at `--runs 20000` (`--strategy random --seed-prefix VIGCHK`) it disappears:

| market | mean leg EV @20k | legs |
|---|---|---|
| Moneyline | −4.5pp | 32,000 |
| Total Goals | −3.6pp | 96,513 |
| BTTS | −3.2pp | 32,349 |
| Total Corners | **−4.1pp** | 96,587 |
| Total Cards | −3.5pp | 96,263 |

Analytic expectation under the proportional overround `odds = 1/(p·(1+r))`
(`MatchModel.cs:106-117`, `r = 0.05`) is `1/(1+r) − 1 = −4.76pp` for every market
regardless of `p`. All five land within noise of it. The n=1000 figure was sampling
noise. Recorded so the next reader does not chase it.

Residual, stated as an observation and **not** a defect claim: the cluster sits
slightly above −4.76pp, and Moneyline is priced by a different function
(`OddsMath.OverroundOdds`, `engine/OddsMath.cs:43-50`, additive-implied) than the
other five. A dedicated high-n per-market vig calibration is worth one bounded run
before playtest conclusions are drawn from EV numbers.

## 4. What needs re-skinning now the redesign has merged

The design system's contract and the shipped market strings disagree. All of these
are **DD questions, not lead calls** — listed with evidence, no decision taken.

### D-01 · Market label vocabulary mismatch

The design system splits a leg into fields; the engine ships one packed string.

| Surface expects | Shipped |
|---|---|
| `MarginLeg{ team, price, market }`, market ∈ `"MONEYLINE"`, `"TOTAL GOALS"`, `"BTTS — YES"`, `"ANYTIME SCORER"` (`components/margin/MarginLeg.d.ts:1-12`) | one string: `"BTTS YES — Away v Home"` (`MatchModel.cs:244`; `SportsbookApp.CompactLegLabel:660-682`) |
| `MarketOffer.line` = `"OVER 2.5 GOALS"`, `"BOTH TEAMS TO SCORE"`, `"VALE ANYTIME"` (`components/form/MarketOffer.d.ts:1-11`) | `"OVER 2.5"` + separate panel title `"GOALS TOTAL"` (`SportsbookApp.cs:318-320`); `"YES"`/`"NO"` (`:331-333`); `"{NAME} [{ROLE}]"` (`:350`) |

The `[FW]`/`[MF]`/`[DF]` role tag has no field in the DS contract at all.

### D-02 · A state word that is not in the design system's vocabulary

The app emits `"RIDING"` for an open ticket (`SportsbookApp.cs:786`, `:895`). The DS
enum for that component is `PENDING | LIVE | GREEN | DEAD | VOID | CASHED OUT`
(`components/records/TicketReceipt.d.ts`, `RevealedState.d.ts:3`) — `RIDING` is not
in it. The two-vocabulary split itself is correct and deliberate (live mirror uses
GREEN/DEAD/VOID, settled ledger uses WON/LOST/VOIDED — `SportsbookApp.cs:785-786`
vs `:1377-1379`, matching `LedgerEntry.d.ts`). Only the open-state word diverges.

### D-03 · Anytime scorer is a one-sided market in a two-price grammar

Scorer is YES-only (`MatchModel.cs:224-225`; one offer per rostered player,
`MatchModel.cs:101-102`). The DS price grammar is explicitly paired — *"no
`disabled` state exists — the other side is `replace`"* (`PriceCell.d.ts:11-12`,
`ui_kits/surething/README.md:41`). How a single-sided market occupies a paired-price
row is unspecified.

### D-04 · S17 exposure that is mine, via a config dial

S17 (offer rule text never truncates — show fewer offers instead) is implemented for
**relic/consumable** shop offers only (`SportsbookApp.cs:961-999`, `EstimateOfferHeight`
+ the `"OffersNotShown"` mechanism). Market offers carry no rule text, so S17 does not
bind them today.

But the PLAYERS tab has **no scroll and no "N not shown"**: it lays offers into a
fixed 412px body (`SportsbookApp.cs:274`) at a 42px row pitch two-up
(`:347-348`). At the shipped `PlayersPerTeam = 7` (`RunConfig.cs:56`) it uses 332px
and fits. **At `PlayersPerTeam ≥ 9` it silently overflows** — offers vanish with no
notice, the exact failure S17 was ruled to prevent. The dial is market-owned, so the
latent break is mine even though the container is not.

### D-05 · Verified clean — no action

- **S16 (LEDGER):** compliant. The desktop icon renders the label `"LEDGER"` while
  keeping `"OldSlips"` as the code identifier (`LaptopOs.cs:259`) — exactly the
  split S16 permits. No user-facing `"Old Slips"` or `"SURETHING LEDGER"` string
  survives anywhere in `.cs` (grep: comments and identifiers only).
- **S3 / two-ink / status-not-colour:** the market layer emits no colour and no

  emits blocker text only (`:155-160`); the console uses `ConsoleColor`, not markup.
  A markup-aware palette scan already guards this (`SureThingPaletteMarkupTests.cs`).
