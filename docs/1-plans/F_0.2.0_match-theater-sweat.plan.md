## Overview

Replace the text-ticker center of the TV sweat with the **match theater**: a top-down
neon-on-black soccer stage where anonymous team-colored dots act out the drama stream.
It is explicitly **a renderer, not a simulation** — every staged moment is keyed by a
`DramaEvent` the engine already emits; between beats an idle possession loop kills time
without signifying. Around the stage: chrome v2 (scorebug with a synthesized score ledger,
breathing win-prob bar, taunting cash-out counter, slip strip), the momentum tape, settle
celebration/sting, and audio v0. Observable result: a full-density 3-leg sweat plays as
60–90 seconds of watchable theater (per the declared duration-acceptance criterion —
early rounds shorter by design), with the cash-out decision live throughout, reviewed by
Allen at five milestone gates.

## Problem Statement

Nine playtests validated the loop and the text sweat's pacing, but text gives the eye
nowhere to live between beats and caps the dread ceiling of the signature moment. The
Phase 2 gate ("strangers name the sweat as the hook") demands a near-final sweat. The
2026-07-07 ruling cut *full 2D sport simulation* as a content-pipeline trap; this plan
threads the needle: design/04's tier-3 "abstract momentum viz" matured into a stage with
actors, capped at ~15 scene templates, zero engine RNG, zero sport logic.

## Solution Architecture

### Theater laws (the guardrails that keep this out of the cut tier-4 trap)

1. **Every staged moment is keyed by a DramaEvent.** If the pitch does something between
   beats, it is idle filler and filler never signifies: idle motion may *restate* the last
   revealed state (territory holds where the live win-prob already is) but must never imply
   new information — no goals, no saves, no win-prob movement during idle; the win-prob bar
   is static between beats.
2. **Presentation-local RNG only** (design/04 diegetic law, same as TV static). The
   theater never touches `RngHub`. Team color assignment is deterministic (name hash).
3. **Causal presentation.** The renderer learns outcomes only when the cursor reveals
   them (playtest #6 law). The score ledger is synthesized causally from beats, with a
   stoppage-time correction at `LegFinal` (below).
4. **The stakes chrome stays dominant.** The pitch is the stage; win-prob bar, cash-out
   counter, and slip strip frame it. Reserved palette (design/08): phosphor green =
   money-good only, hot red = money-bad only, gold = cash-out only, cyan = VOID.
   Therefore: **no red team dots, no money-green pitch** — near-black pitch, thin neon
   line markings, team colors from a non-reserved neon pool (electric blue, magenta,
   orange, violet, teal, white; home picks by FNV name-hash → pool index, away takes the
   next non-clashing entry). Keepers get a brightened variant; ball is white.

### Engine delta (the only one): fewer, bigger beats + progressive density

- `DramaConfig`: `MinEventsPerLeg 5 → 3`, `MaxEventsPerLeg 10 → 5` (**bait** — M-T1 tunes
  so a full-density 3-leg sweat lands 60–90s under the pacer table). Final-leg ×2 unchanged.
- Progressive sweat density (design/04, playtest #1): `DramaConfig` gains a round ramp —
  `EarlyMinEventsPerLeg = 2`, `EarlyMaxEventsPerLeg = 4`, `DensityRampRounds = 3` (bait).
  Exact semantics (so implementations and golden pins cannot diverge):

  ```
  EventBoundsForRound(int round)   // round is 1-based, Run's current round number
    if DensityRampRounds <= 1 or round >= DensityRampRounds:
        (min, max) = (MinEventsPerLeg, MaxEventsPerLeg)
    else:
        t   = (round - 1) / (double)(DensityRampRounds - 1)    // 0.0 at round 1
        min = (int)Math.Round(EarlyMinEventsPerLeg + t * (MinEventsPerLeg - EarlyMinEventsPerLeg),
                              MidpointRounding.AwayFromZero)
        max = (int)Math.Round(EarlyMaxEventsPerLeg + t * (MaxEventsPerLeg - EarlyMaxEventsPerLeg),
                              MidpointRounding.AwayFromZero)
    // normalization applies to BOTH branches — degenerate configs clamp, never crash
    // (the sim sweeps config values programmatically; same rule as the existing k<1 clamp)
    if (min < 1) min = 1;  if (max < min) max = min;
    return (min, max)
  ```

  `BuildLegPath` draws `baseCount` from these bounds (`NextInt(min, max + 1)` — one draw,
  same structure as today), **then** applies `FinalLegBudgetMultiplier` to the final leg and
  the existing `k < 1` clamp, both unchanged. `DramaGenerator.BuildTicketPaths` gains an
  `int round` parameter; `Run.cs:281` (LockRound) passes it.
- Draw structure per leg is unchanged (one count draw, per-step noise, near-miss roll) —
  only values move. **Drama-stream goldens re-pin (intended); outcome-stream pins must be
  shown byte-identical** (outcomes come from the Outcomes stream, untouched).
- Fewer beats = fewer cash-out repricings = bot cash-out behavior shifts ⇒ **full sim
  gate campaign re-runs** (see Balance impact).

### Beat → scene vocabulary (the ScenePlaybook, ~15 templates, ordered resolver)

Direction = sign of the win-prob move for the picked side (exactly `EventText.cs`'s rule:
compare `WinProbAfter` to the previous beat's, first beat against the leg's `TrueProb`).
The choreographer resolves a beat to a `SceneSpec` through an **ordered resolver over the
actual `DramaEvent` fields** — not a flat key tuple:

```
Resolve(evt, dir):
  1. evt.Type == LegFinal        → outcome scene from the revealed result
                                    (WinProbAfter 1.0 → #12 Won, 0.0 → #13 Lost).
                                    The pending-window kill-scene suspension lives here;
                                    a SUSPENDED LegFinal's continuation is chosen from the
                                    FINAL ticket-local grade after resolution (which the
                                    Whistle may have flipped) — never from WinProbAfter.
                                    See pending-window choreography.
  2. evt.Tag == NearMiss         → #7 (dir up, "miracle brewing") / #8 (dir down,
                                    "slipping away"). Never a goal, regardless of Type.
  3. base scene by (Type, dir)   → Score: #1/#2 · BigPlay: #3/#4 · Momentum: #5/#6
                                    (Momentum with Tag==Calm uses the #11 calm variant).
  4. overlays (playback modifiers, never template choice):
       Tag == LeadChange → #9 turnover-transition intro composed onto the base scene
       Tag == Swing      → #10 urgency modifiers (actor speed, pass tempo)
```

Steps 1–3 cover every `(Type, dir, Tag)` triple, so the resolver is **total by
construction over all 40 raw combos**; unreachable combos (per generator invariants:
`BigPlay×Calm` and `Momentum×Swing` cannot occur since Swing needs `|Δp| ≥ 0.10 >` the
0.07 Score threshold; `Decisive` only on `LegFinal`) resolve through the same path with no
special-casing. #14 (kickoff / post-goal restart) is structural playback, not beat-keyed;
#15 (generic fallback: neutral attack fizzles) guards future enum additions — the resolver
falls back rather than throws.

| # | Scene | Sketch |
|---|---|---|
| 1/2 | Goal for/against | buildup → shot → **goal**, net ripple, restart — chalked-off variant (VAR disallow, neutral chrome) when the live-lead clamp blocks the increment |
| 3/4 | Breakaway goal for/against | long carry, far-post finish, emphatic — same chalked-off variant under the clamp |
| 5/6 | Territory shift for/against | possession squeeze, line advances |
| 7/8 | Near-miss hope/scare | ball across the open goalmouth / off the bar, keeper full-stretch — **no goal** |
| 9 | LeadChange overlay | steal → transition intro |
| 10 | Swing overlay | urgency modifiers |
| 11 | Calm variant | midfield recycling, slow triangles |
| 12/13 | LegFinal Won/Lost | decisive sequence → **GREEN/DEAD slam** + whistle, celebrate/collapse |
| 14 | Kickoff/restart | structural (leg open, post-goal) |
| 15 | Fallback | neutral attack fizzles out |

Repetition control: each template has 2–3 spatial variants chosen by `Step` index
(deterministic, EventText's variant trick). Future scenes = new resolver rows, no engine
change.

### Pending-loss window choreography (the clippable moment)

The window opens *before* the killing beat lands. The choreographer plays the kill
scene's buildup and **freezes at the suspension point — opponent's shot mid-flight** —
while the `[M]ulligan / [R]eview / let it die` prompt shows. On resolution the suspended
scene plays an explicit **continuation chosen from the final ticket-local grade** (single
presentation authority — the resolver's `WinProbAfter` reading never decides a suspended
scene's ending):
- **Mulligan → VOID**: no goals — stage desaturates to cyan VOID treatment, scene
  dissolves, ledger stays frozen.
- **Whistle success → Won**: the frozen shot resolves as a keeper save / wide, then the
  continuation **stages** the stoppage-time counter goal(s) the ledger correction needs
  (sucker-punch break up the other end) until the picked team is strictly ahead →
  #12 GREEN slam + whistle.
- **Decline / whistle fail → Lost**: the ball completes its flight, routed through the
  same clamp + correction computation as every goal: the killing shot **commits only if
  the opponent is not already strictly ahead**; if the entry score already satisfies Lost
  (−1), it stages as chalked-off — disallowed at the death, the whistle still confirms
  Lost — so `MaxLiveLead` is never violated. Any further staged opponent goal(s) only if
  the correction needs them → #13 DEAD slam. (Tests cover entry leads −1/0/+1 for both
  final outcomes.)

The same staging rule governs an unsuspended `LegFinal`: any correction goal(s) play
inside scene #12/#13 before the whistle. **Goal-playback invariant: every ledger
increment corresponds to a goal that visibly played on the pitch** — the score can never
jump without a goal being staged.

### Score ledger (new presentation logic — causal + honest)

_AMENDMENT (playtest #14, 2026-07-19): goal attribution gains a second source — **prob
reconciliation**. The scoreboard is a lagging quantized rendering of the live probability:
prob ≥ `ReconcileHighBand` (0.70) implies picked strictly ahead, ≤ `ReconcileLowBand`
(0.30) implies opponent strictly ahead; when the board disagrees, the next beat moving in
that direction stages the reconciling goal regardless of beat type (the choreographer
upgrades the scene to the goal template), through the same live-lead clamp. Mid-band
scorelines within the clamp are never dragged back to level. This generalizes the
stoppage-time correction to mid-leg and kills the "0-0 at 90%" / "leading at 25%"
dissonance Allen flagged. The paragraphs below describe the original type-based source,
which remains._

- Score/BigPlay beat, up ⇒ picked team goal; down ⇒ opponent goal. Momentum/NearMiss ⇒
  no goal. Running score shows on the scorebug.
- **Live-lead clamp** (`MaxLiveLead = 1`, dial): a goal that would push the live lead
  beyond ±1 stages as the **chalked-off variant** of its goal scene — ball hits the net,
  VAR flag, disallowed — full beat drama, *no ledger increment*. The variant belongs to
  **every goal-producing scene (#1–#4)** and to the `LegFinal` killing shot (above); the
  treatment is VAR-disallow only, styled in neutral broadcast chrome (white flag /
  crossed-out score) — **never a red card**, because hot red is reserved for money-bad
  (design/08) and a card is not a money signal. Consequence, by construction: the
  scoreline entering any `LegFinal` is within ±1, so a correction needs **at most
  2 staged goals** (from −1 to +1); a property test over generated paths pins the bound.
  Deliberate drama law, not just budget hygiene: the theater tells one-goal-game
  stories — blowout scorelines never sweat.
- **Commit timing**: a goal commits when its beat's scene *completes playback*, never on
  `MoveNext` — so a suspended scene has committed nothing.
- At an unsuspended `LegFinal` (outcome now revealed): if the winner is not strictly
  ahead, award stoppage-time goal(s) with the final scene until they are — "won it at the
  death" is soccer-honest and the live win-prob was always the real signal.
- **Pending-loss window**: while the window is open the ledger is frozen — no goal, no
  correction. It commits only as the grade-chosen continuation plays (see pending-window
  choreography), from the final ticket-local grade:
  - *Mulligan* → leg VOID: no stoppage-time correction; the scoreline freezes as-is under
    the cyan VOID treatment (a voided match needs no coherent final score).
  - *Whistle success* → grade Won: staged counter goal(s) bring the picked team strictly
    ahead.
  - *Declined / whistle fail* → grade Lost: the killing goal (plus any further staged
    goal(s)) bring the opponent strictly ahead.
- **Goal-playback invariant**: ledger increments fire *only* from goal-playback
  completion events — base scenes and staged correction goals alike. The scoreboard can
  never move without a goal on the pitch.
- EditMode tests pin all four paths (plain final, void, flipped-to-Won, confirmed-Lost)
  **plus the invariant**: every increment in a played-through path maps 1:1 to a staged
  goal playback.

### SweatPacer (dials, all serialized presentation config — never engine)

Durations keyed by the *resolved scene class* (all dials, initial values): calm/territory
3.0s · goal 5.0s · breakaway goal 5.5s · +1.0s LeadChange overlay · near-miss 7.0s + 0.5s
hold · LegFinal 8.0s with pre-reveal hold. Ledger-correction goals are **separately
timed sub-scenes** (2.5s each, count 0–2 bounded by the live-lead clamp) appended to the
`LegFinal` scene — they are outside the 3–8s beat-scene band by classification, so a full
final whistle sequence may run 8–13s. Idle loop fills scene gaps ≤1s. Sitting/standing
pause law (design/04) unchanged.

**Duration acceptance (declared before tuning — no post-hoc bands, the sim's own
hygiene rule):** over ≥1,000 engine-generated **full-density** (round ≥
`DensityRampRounds`) 3-leg beat paths, the summed scene durations under the pacer table
(scenes + holds **+ the actual per-path correction-goal count**, computed by replaying
the ledger's attribution, clamp, and correction rules over each path; idle gaps and
pending-window wait excluded) must have **median in [60, 90]s, ≥80% of paths in
[50, 100]s, and a worst-case path ≤ 110s**. An EditMode test computes this from the
pacer dials + `DramaGenerator` paths; M-T1 tunes budgets and M-T3 tunes dials until it
passes. Early rounds are deliberately shorter (progressive density is the onboarding
mechanism) and are exempt from the 60–90s band.

### Momentum tape

One strip per leg of the ticket (matches Allen's sketch reading): each beat appends a dot
in the beneficiary's team color, sized by `|Δp|` band. Current leg's strip grows live;
resolved legs collapse to a thin capped strip (GREEN/DEAD/VOID cap). Data comes from
`SweatPresentationModel` beat history — same source as the stage, cannot disagree.

### Audio v0 (TvAudioDirector)

Procedural-first (keeps the zero-asset discipline for the slice): filtered-noise crowd
bed whose volume/brightness tracks live win-prob distance from 0.5 and tension tag;
synthesized stings (goal hit, near-miss riser + cut, whistle, GREEN/DEAD slams, cash-out
ka-chunk per design/08). Decision point at the M-T5 gate: procedural is enough for the
slice, or a CC0 pack pass is warranted. Audio sources live on the TV (diegetic, design/08).

## Technical Considerations

- **Pattern Usage**: touches laws #2 (determinism — no new engine RNG; presentation-local
  only), #3 (fixed universe — cursor-stepping renderer, causal score synthesis), #8
  (drama not sports — the theater renders the authored stream), #10 (docs-first —
  design/04 + DECISIONS in M-T1). Follows existing patterns: EventText's direction/variant
  rules, TvLight palette law, code-built UGUI, model-layer-first (SweatPresentationModel).
- **Determinism**: drama-stream draw *values* change (budget bounds), draw *structure*
  does not; drama goldens re-pin intentionally, outcome pins proven unchanged. Theater
  consumes zero engine RNG; replays of a seed produce identical beat streams (dot
  micro-motion may differ — acceptable, it never signifies).
- **Balance impact**: yes — cash-out repricing frequency changes bot behavior. Full
  G1–G6 + per-item audit re-run; tune on `TUNE-`, freeze commit, validate once on fresh
  `HOLDOUT3-` at 50k/batch; `sim-report-5.md` + holdout report are the of-record artifacts.
  Skilled band 4.5–8% (floor re-banded 5% → 4.5%, Allen 2026-08-08) / median death ≥5 must re-hold.
- **Engine/client boundary**: engine gets only the budget/ramp/`round` plumbing. All
  theater logic is Unity-side; `SweatPresentationModel` is pure C# (no UnityEngine) for
  EditMode testability. Console inherits pacing, stays text. Sim bots unaffected by
  presentation (they step beats instantly).
- **Effect pipeline compliance**: untouched. Cash-out, Mulligan, Whistle verbs already
  exist; the theater only renders them.
- **Test pins**: drama goldens re-pin; DramaConfig default assertions move (a tuning
  change is a test change); sim-report gate numbers re-issue as report 5.
- **Risk and reversibility**: the text ticker renderer stays behind a serialized
  `theaterEnabled` toggle through M-T4 (A/B at playtests, instant rollback); engine
  change reverts by config + re-pin. Biggest creative risk is the idle loop reading as
  fake — mitigated by law #1 (filler never signifies) and the M-T2 gate existing
  precisely to catch it. Schedule risk: ScenePlaybook is the long pole; the fallback
  scene (#15) means partial vocabularies still play full sweats.
- **Architecture memory**: `docs/ARCHI.md` §14 gains the theater component map; §11 notes
  the round-ramped budgets (same implementation, M-T1 and M-T5 bookend the doc updates).
