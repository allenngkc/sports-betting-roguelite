# Phase V1 — the vocabulary, build spec

**Status:** written while Campaign A2 ran, before any V1 code. Ruled inputs are settled — Allen's
draws rulings plus §12.3's re-derivation under draws-exist — so this specifies HOW, not WHETHER.

**The set is closed.** No market is added here that §12.3 did not rule in, and nothing ruled in is
dropped. HT/FT stays frozen (it is still the only market needing new sampler draws).

## 1. The domain-shape change, and its blast radius

`MarketSelection` is `{ Kind, Line, Choice, PlayerIndex }`. Team totals and handicap need a **team**;
correct score needs a **score**. Neither fits, and neither may be packed into `Line`.

Add **named** fields — `Team` (`Side?`), `ScoreHome`, `ScoreAway` (`int`, −1 when unused). S22 struck
the packed display string on exactly this principle; a packed *numeric* field is the same defect in
another costume, and a future reader decoding `Line = 21.0` as "2-1" is the failure it invites.

Blast radius, all compile-enforced: `Equals` / `GetHashCode` / `==` (mechanical — `HashCode.Combine`
takes up to 8 components, this needs 7), the `MarketProbEst` dictionary key in `sim/BotState`,
`Siblings()`, `MatchModel.Fields()`, `DisplayLabel()`. The board index added in Phase 0 keys on
`MarketSelection`, so it inherits the new equality for free.

## 2. The kinds, their pricing, and their grading

Every one grades as a predicate over the **existing** `MatchStatLine`. No sampler change, no new
RNG, **no golden re-pin** — that property is what keeps V1 cheap and it must not be given up
casually.

| Kind | Selections | Price = P(...) | Grades on |
|---|---|---|---|
| `DoubleChance` | 1X, X2, 12 | union of two 1X2 outcomes | `line.Result` ∈ pair |
| `Handicap` | home/away ∓1.5 | `P(h − a > ±1.5)` | signed goal margin |
| `TeamTotalGoals` | team × {0.5, 1.5} × O/U | per-team goal marginal | `HomeGoals` / `AwayGoals` |
| `CorrectScore` | every (h,a) with p ≥ **2%** | the joint cell | exact score match |
| `WinningMargin` | 1, 2, 3+ | `P(\|h − a\| = k)` | `abs(h − a)` |
| `TotalGoalsOddEven` | odd, even | `P((h+a) mod 2)` | parity |
| `TeamTotalCorners` | team × 4.5 × O/U | per-team corner tail | `HomeCorners` / `AwayCorners` |
| `TeamTotalCards` | team × 2.5 × O/U | per-team card tail | `HomeCards` / `AwayCards` |
| `PlayerMultiScorer` | each listed player, 2+ | `1 − P(0) − P(1)` under the same weights | count in scorer list |

**Draw-no-bet is deferred out of V1 unless it comes back ruled.** It needs void-on-grade, which
changes the leg lifecycle (`PotentialPayout` reads `ActiveLegs`) rather than the market model, and
that is a different kind of change from everything above.

## 3. The three constraints that must be tests, not intentions

1. **Offerability.** `MatchModel.Offer` throws when odds ≤ 1.0, i.e. p ≥ 0.95238. Handicap ±2.5
   reaches **0.984** and team-total 2.5 reaches **0.949** — both measured, both excluded for it.
   A test must sweep the full latent box and assert every emitted offer prices above 1.0, so a
   future line change fails a suite in seconds instead of a campaign in half an hour.
2. **Correct score is capped at the ratified 2% floor** — 12–16 rows, longest 47.3×, inside the
   existing 62.6× scorer tail. The cap is what keeps the vocabulary from becoming an economy change.
3. **Exhaustiveness.** `OverroundOdds(IReadOnlyList<double>, …)` rejects a set that does not
   partition the outcome space. Double chance and correct score must NOT be priced through it as
   families — double chance's three selections overlap, and a floor-truncated score board is not
   exhaustive. Both are priced per selection at the standard overround.

## 4. Bot treatment — decided now, so G7 is not a surprise

`Siblings()` may only carry a market whose set is complete. Therefore:

- **Two-way, bot-priced:** handicap, team totals (goals/corners/cards), odd/even.
- **Bot-EXCLUDED, and each needs the M1 *measured* treatment** (random-bot reachability proving
  DECLINED rather than BLOCKED): correct score and winning margin (floor-truncated / one-way sets),
  player 2+ (inherits the AnytimeScorer human-agency exclusion), double chance (its selections
  overlap, so normalizing them is not de-vig).

An exclusion asserted without that measurement is the silent skip G7 exists to catch — the BTTS
entry is the pattern to copy, including its expiry condition.
