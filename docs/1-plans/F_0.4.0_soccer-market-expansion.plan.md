## Overview

The prototype's betting surface is moneyline-only. This slice makes soccer a real board: each
matchup offers **six market kinds** — Moneyline (exists), Total Goals O/U, Both Teams To Score,
Total Corners O/U, Total Cards O/U, and Anytime Goalscorer — with **3-line ladders**
(main ± 1) on the three counting markets. Observable result: the SureThing board gains a match
detail view with market tabs; the console client gains the same board; the sweat theater stages
corner and booking scenes with market-aware scoreboard chrome; cash-out stays provably honest
for every market; the sim re-passes G1–G6 with market-aware bots.

Decisions frozen in grilling (2026-07-20, Allen):

1. v1 markets: ML, Total Goals, BTTS, Total Corners, Total Cards, Anytime Goalscorer. All
   second-wave markets (handicap, team totals, double chance, correct score, HT/FT) → v2.
2. **One leg per match per ticket** (already enforced at `Run.cs:181`) — SGP correlation
   pricing is dodged structurally; revisit v2.
3. **No draws in v1** — every market two-way (Anytime Scorer is one-way yes). The stat-line
   sampler conditions the score on the already-drawn winner, so ties are unrepresentable.
4. Alt lines: main ± 1 (3 lines) per counting market.
5. UI: **match detail view** — board keeps ML rows; a match opens a detail page with market tabs.
6. Counting markets get a **public noisy stats signal** (the records pattern extended): hidden
   per-team latent rates, displayed as noisy per-game averages on the detail page.
7. Anytime Goalscorer ships in this slice as its **own late phase** (players are new entities).
8. Cash-out honesty is the priority — see Solution Architecture for the by-construction argument.

## Problem Statement

`Matchup` carries exactly one market: `TrueHomeProb` + two odds, resolved by a single
`Side? Result`. `Pick` is `(matchupIndex, side)`. Every consumer — console grammar, Unity
`BetslipModel.Toggle(matchup, side)`, sim bots, drama, cash-out — assumes the moneyline shape.
There is no per-match stat line, so nothing besides the winner can be graded, and the theater's
score is pure presentation (`ScoreLedger` synthesizes it from the prob walk).

## Solution Architecture

### The stat line is the new ground truth

At `LockRound`, each matchup bakes a **`MatchStatLine`** — final score, corners (home/away),
cards (home/away), and (Phase 4) scorer attributions — from the Outcomes stream, in slate
order, bet or not (the fixed universe, unchanged law). Every market grades as a **predicate
over the stat line**; `Matchup.Result` becomes a derived view (score winner) so existing code
keeps compiling. Two tickets betting different markets on the same match can never contradict,
because they grade from the same baked line.

Sampling order per matchup (constant draw count — bet choices can never shift the universe):

1. **Winner** ~ Bernoulli(TrueHomeProb) — the exact draw made today, kept first so the ML
   universe shape is preserved.
2. **Score** — one uniform draw indexing the enumerated conditional distribution
   P(h, a | winner) over a truncated grid (loser < winner ≤ `MaxGoalsGrid`). No rejection
   loops; one draw, always.
3. **Corners home, corners away** — truncated Poisson(κ_h), Poisson(κ_a), one draw each.
4. **Cards home, cards away** — truncated Poisson(δ_h), Poisson(δ_a), one draw each.
5. (Phase 4) **Scorer attributions** — drawn from a new **match-keyed derived stream**:
   `RngHub.DeriveMatch(round, matchupIndex, purpose)` minting `"{round}#M{matchupIndex}#{purpose}"`
   (same FNV keying discipline as the existing 5-component `Derive`, new overload in
   `engine/RngHub.cs`). Call flow: `Run.LockRound` → `MatchModel.SampleScorers(statLine,
   roster, RngHub.DeriveMatch(round, i, "scorers"))`, one draw per goal. Because scorers never
   touch the Outcomes stream, Phase 4 adds **zero** draws to it — no second golden re-pin, and
   the variable draw count (up to 8+7 goals) is harmless inside an isolated per-matchup stream.

### Latent rates and the stats signal

`SlateGenerator` gains per-team **latent rates**, drawn on the Slate stream alongside strength.
Real-soccer anchors so the satire lands: λ ≈ 1.35 goals/team (total ≈ 2.7), κ ≈ 5 corners/team
(total ≈ 10), δ ≈ 2.2 cards/team (total ≈ 4.4) — which is why the main lines are 2.5 / 9.5 / 4.5.

Exact model (constants are `RunConfig` dials with these defaults; Phase 5 may re-tune them, and
tests pin the tuned values):

- Strength tilt `g(p) = 0.6 + 0.8p` (linear, `g(0.5) = 1`) — stronger teams attack more.
  Discipline tilt `h(p) = 1.15 − 0.3p` — underdogs foul more.
- Per-matchup latent draws, **in this order, constant count (+9 Slate draws per matchup)**:
  goal tempo `t_g ~ U[0.85, 1.15]` (1), corner tempo `t_c ~ U[0.8, 1.2]` (1),
  spice `s ~ U[0.8, 1.2]` (1), then six signal-noise draws (below).
- Rates: `λ_h = BaseGoalRate·t_g·g(p)`, `λ_a = BaseGoalRate·t_g·g(1−p)`;
  `κ_h = BaseCornerRate·t_c·g(p)`, `κ_a = BaseCornerRate·t_c·g(1−p)`;
  `δ_h = BaseCardRate·s·h(p)`, `δ_a = BaseCardRate·s·h(1−p)`.
- **Displayed signal** (the records pattern — free information, honestly noisy): per team,
  per stat (goals-for, corners, cards — 3 × 2 teams = 6 draws), shown average
  `= rate + U(−σ, σ)` with `σ = SignalNoise · rate / √PriorGames`, rendered to one decimal
  ("GF 1.8 · COR 5.2 · CRD 2.1"). The Phase 5 skilled estimator inverts exactly this with
  pseudo-count shrinkage: `rateHat = (PriorGames·displayed + ShrinkWeight·baseRate) /
  (PriorGames + ShrinkWeight)` (`ShrinkWeight` a sim-side dial, default 6), then the same
  enumeration pricing over `rateHat` → EV per selection, bet when EV clears the strategy's
  existing edge threshold (it never reads `TrueProb`, per the `SkilledStrategy.cs:25` law).
- A Phase 1 test pins the Slate-stream draw order so any reordering fails loudly.

### Pricing is exact, not sampled

True probabilities are **pure functions of the latents** (no RNG): enumerate the same
truncated grids the sampler uses. Total Goals over ℓ:
`P = p·P(h+a > ℓ | home wins) + (1−p)·P(h+a > ℓ | away wins)` — the unconditional law of the
generative model, so pricing and grading share one distribution. BTTS: `P(h ≥ 1 ∧ a ≥ 1)`.
Corners/cards: independent-Poisson tail sums. Each two-way line is priced through the existing
`OddsMath.OverroundOdds` (same 5% overround as ML). Invariants pinned by tests: ladder
monotonicity (P(o1.5) > P(o2.5) > P(o3.5)), implied-prob sum = 1 + overround per line,
grade-vs-price consistency on forced stat lines.

### Cash-out honesty — exact at the anchors, no regression in between

The honesty boundary already exists and is market-agnostic:

- `Leg.TrueProb` (per-market model marginal) anchors the drama walk (`DramaGenerator.cs:74`)
  and prices unstarted legs in `SweatSession.RawCashOutFair` (`SweatSession.cs:292`).
- `DramaEvent.WinProbAfter` is the live prob the cash-out reprices on (`SweatSession.cs:135`).
- `OddsMath.CashOutFair` is untouched.

Scope of the claim, stated precisely (Sol review round 1): what is **exact** is the anchor
prob (each leg's walk starts at its market's true model marginal), the pricing of unstarted
legs, and the cash-out formula itself. The **intermediate** beats inherit the documented v0
simplification (`DramaGenerator.cs:6-11`): the walk is approximately honest — outcome-drifted,
not a martingale. That approximation is pre-existing, applies to moneyline today, and is
inherited *identically* by every new market because the generator is market-blind (it reads
only `leg.TrueProb` and `leg.State`; no market-specific branch may be added to it). New Phase 1
test: a Monte Carlo calibration smoke — mean first-beat `WinProbAfter` over many seeds matches
the leg's true p within CI, run for an ML leg and a counting-market leg, pinning that no market
prices worse than ML does today. Upgrading the walk to a true martingale bridge stays a
backlog item, out of this slice's scope. `DramaGenerator` and `SweatSession` require **no
changes**.

### The item system generalizes for free

`RelicEffects.cs` contains zero references to `Side`, `TrueProb`, `Matchup`, or `.Odds(`
(verified by grep). Profit Boost rewrites `Leg.OfferedOdds`; Mulligan voids a leg; Ref's
Whistle re-rolls at the captured `WinProbAfter`; factors ride `Ticket` — all market-agnostic.
Re-audit at Phase 1 review.

### Domain shape

```
enum MarketKind { Moneyline, TotalGoals, BothTeamsToScore, TotalCorners, TotalCards, AnytimeScorer }

readonly struct MarketSelection   // Kind + Line (counting markets) + Choice (Home/Over/Yes
                                  // vs Away/Under/No) + PlayerIndex (Phase 4, else −1)

sealed class MarketOffer          // MarketSelection + TrueProb + Odds — the priced board,
                                  // built at slate generation, frozen (locked odds law)

Pick        → (MatchupIndex, MarketSelection); keeps a Pick(int, Side) ML convenience ctor
              so bots/tests/BetslipModel churn is mechanical
Matchup     → gains Markets (the board), stat latents, displayed TeamStats; TrueProb(sel),
              Odds(sel); Result becomes derived from StatLine
MatchStatLine → HomeGoals/AwayGoals/HomeCorners/AwayCorners/HomeCards/AwayCards (+ scorers P4)
Leg         → stores MarketSelection + display label; TrueProb/State delegate to
              Matchup.TrueProb(sel) / StatLine predicate
```

The one-leg-per-match guard at `Run.cs:181` (distinct matchup indices) is **kept verbatim** —
it now enforces the SGP v1 decision across markets.

### Phase 3 — Theater: corner & booking scenes, market chrome (~1.5 days)

**Files**: `SweatPresentationModel.cs` (ScoreLedger → generalized count ledgers),
`ScenePlaybook.cs` (+ `CornerFor/CornerAgainst`, `Booking` templates), `TheaterChoreographer.cs`,
`TheaterStage.cs` (corner-kick + booking staging), `SweatPacer.cs`, `MomentumTape.cs`,
`TvAudioDirector.cs` (booking whistle, corner riser), `SweatFlavor.cs`/console `EventText.cs`
vocabulary, EditMode/PlayMode tests.

**Modifications**:

- The sweated leg's market selects its scene vocabulary: corners legs stage corner events that
  move a corner count; cards legs stage bookings; goals/BTTS legs reuse goal scenes; ML
  unchanged. Count ledgers follow the ScoreLedger laws mid-sweat: lagging quantized rendering
  of the walk, playback-completion commits, clamp against the live prob direction.
- **Endpoint convergence law (new, Sol round 1)**: `MatchStatLine` is ground truth, so every
  ledger must land **exactly** on the baked values at `LegFinal` — goals ledgers on the final
  score (all markets, ML included), corner/card ledgers on the baked totals when that market
  is sweated. The ledger plans its remaining reveals against the baked endpoint (read-only
  engine state; presentation still consumes no RNG). Tests pin convergence on forced stat lines.
- **Batched-count pacing rule (Sol round 2)**: a baked corner total (~10) exceeds a leg's
  2–5 beats, so beats reveal **batched count deltas**: the ledger pre-plans a per-beat delta
  schedule (each delta ≥ 0, possibly > 1, monotone partial sums, summing exactly to the baked
  total; commentary covers multi-count reveals — "three corners in that spell"). Count and
  price move together at each scene's payoff, so the causal reveal law holds bit-for-bit; the
  final beat's delta is bounded by the schedule (no unbounded reconciliation dump), and sweat
  duration stays inside the 60–90s law — a test pins schedule-sum exactness and per-beat
  delta bounds on forced stat lines.
- **Selection-aware direction rule (new, Sol round 1)**: For/Against and hope/dread derive
  from the **picked selection**, not a team — a count event always increments the total, and
  its money-direction is the sign of the beat's Δp toward the pick. An Under bettor dreads
  corners; a No-BTTS bettor dreads the underdog's first goal. `SceneSpec.ForPicked` keeps its
  name; its meaning is "moves toward the picked outcome."
- Scoreboard chrome chip for the active market ("CORNERS 7–3 · O 9.5", "CARDS 4 · U 4.5",
  "BTTS 1/2"). Causal reveal law holds: chrome and market reprice only at scene payoff.

### Phase 4 — Anytime Goalscorer: players end-to-end (~1 day)

**Files**: `engine/Domain.cs` (`Player` on `Team`: name, role, scoring weight),
`engine/RngHub.cs` (new `DeriveMatch(round, matchupIndex, purpose)` overload),
`engine/Run.cs` (LockRound scorer-sampling call), `engine/MatchModel.cs` (attribution via

console + `SportsbookApp` **Players** tab (grammar `1S3`), `TheaterStage.cs` (named actor

**Roster stream-isolation rule (Sol round 2)**: rosters (names, roles, scoring weights) are
generated from `DeriveMatch(round, matchupIndex, "roster")` at slate-generation time —
**zero draws on the sequential Slate stream**, so every pre-Phase-4 pin survives. Scoring
weights are part of the pricing latents (Anytime Scorer true p is a pure function of them).
New Phase 4 **golden-preservation test discipline**: the Phase 1 golden pins must pass
untouched at the end of Phase 4 — a golden failure in this phase is a bug, never a re-pin.

## Technical Considerations

- **Pattern usage (ARCHI §5)**: touches laws 2 (determinism), 3 (fixed universe), 4 (locked
  odds — `MarketOffer` frozen at slate gen), 5 (legible payoffs — every market is the
  four-number model over an exact distribution), 8 (drama not simulation — the stat line is
  sampled, the walk is authored). Laws 6, 7, 9 untouched.
- **Determinism**: Slate stream gains +9 latent/signal draws per matchup; Outcomes stream
  gains stat-line draws (constant count per matchup). **Golden-seed pins break once, at
  Phase 1 — intended**; re-pin with the settlement-invariance note pattern from F_0.2.0 M-T1,
  covering both the engine pins and the Unity `GoldenReplay` fixture. Phase 4 scorers use a
  derived per-matchup stream, so **no later phase re-pins**. Drama stream draw structure
  unchanged; paths differ only because leg TrueProb values do. No presentation code consumes
  engine RNG (unchanged).
- **Balance impact**: Phases 1–4 leave bot behavior ML-only → `--gates` runs as regression
  smoke each phase (numbers shift with the re-pinned universe; bands must hold). Phase 5 is
  the real re-tune: G1–G6 + audit + HOLDOUT3. New-market pricing uses the same 5% overround,
  so per-bet EV is unchanged at equal p — the EV surface changes only through bot selection.
- **Engine/client boundary**: all pricing/grading in `engine/`; clients render boards and
  validate picks. No new engine verbs; `PlaceTicket` signature unchanged; `IStrategy`
  unchanged (Pick carries the market).
- **Effect pipeline compliance**: no new hooks; no factor-map changes; verified no item reads
  market internals (grep audit above, re-checked at Phase 1 review).
- **Test pins**: golden seeds (once), pricing worked numbers, ladder monotonicity, stat-line
  invariants, count-ledger laws, board/betslip EditMode pins. A line/rate tuning change is a
  test change.
- **Risk and reversibility**: each phase is one reviewable commit on a `feat/soccer-markets`
  branch; rollback = revert the phase commit. No saves/persistence exist, so no migration.
  Failure mode to guard in review: pricing/grading divergence (a market priced off one
  distribution but graded off another) — killed structurally by the shared enumeration spine.
- **Architecture memory**: `docs/ARCHI.md` §9/§11/§14 updated in the same change as each
  phase that shifts them; design doc `design/12-soccer-markets.md` + DECISIONS.md entries
  written at freeze (docs-first law).
