## 2. Declared product decisions — do not invent policy

1. Bots cover **Moneyline + TotalGoals + BTTS + TotalCorners + TotalCards**. AnytimeScorer is
   **bot-excluded** (no public weight signal; declared human-agency market, the Ask-the-Manager
   precedent). Skip scorer offers in every strategy.
2. **NaiveStrategy stays exactly as-is** (ML favorites). G1's meaning must not shift.
3. **RandomStrategy**: uniform selection over the full two-way board excluding scorer offers
   (currently an ML coin-flip). Same leg-count and staking behavior otherwise.
4. **SkilledStrategy** (the core of this phase):
   - Estimate per-team latent rates from the DISPLAYED `TeamStats` signal with pseudo-count
     shrinkage: `rateHat = (PriorGames·displayed + ShrinkWeight·baseRate) / (PriorGames +
     ShrinkWeight)`, `ShrinkWeight` a sim-side dial (default 6), `baseRate` = the matching
     `RunConfig` base dial (BaseGoalRate / BaseCornerRate / BaseCardRate).
   - Compute market probabilities with the bot's OWN sim-side truncated-Poisson / score-grid
     math. Deliberately independent of engine internals: the strategy must NEVER read
     `TrueProb`, `Latents`, `StatLine`, `Matchup.Dist`, or any engine pricing helper. The
     existing records-only `pHome` estimation stays as-is for ML (see the law in
     `sim/SkilledStrategy.cs` header). Bot-model-vs-house divergence is fine — it's a bettor.
   - EV per selection = `pHat × offeredOdds − 1`. Market selections join the existing
     candidate/plan machinery as parlay candidates alongside ML; keep at most the best-EV
     selection per matchup; existing edge thresholds, leg caps, and stake sizing unchanged.
   - Preserve the extensible-virtuals pattern (archetype subclasses override behavior).
5. **MartyrStrategy / ArchetypeStrategies**: compile-level updates only; behavior unchanged.
6. **Metrics → BatchSummary → Analysis/Report**: add per-market-kind EXPOSURE columns (legs
   placed, stake share) and realized EV per kind. OBSERVATIONAL ONLY — no new gates, G1–G6
   unchanged. Scorer-kind zero exposure is expected; the report notes it as declared.
7. **No `engine/` changes at all.** If you believe one is needed, STOP and report why instead.
8. Sim-side dials (ShrinkWeight etc.) live in the sim (e.g. strategy ctor constants or
   `CliOptions` if a flag already fits the pattern), never in `RunConfig`.
