## 1. TWO BINDING CONDITIONS ON THE WINDOW ITSELF

These are named now, before the shoot, because **a capture can arrive and still not close its item**
— and both of these would produce a set that looks complete and answers nothing.

### 1.1 Each tab must be shot at its FULL SCROLL EXTENT

The C19 question in `markets-surface-research-2026-08-16.md` §5b is *"do the eight tab-less market
kinds appear anywhere on ENTRY."* A tab's **first screen alone cannot answer it** — a Handicap or
Correct Score block nested below the fold inside `GOALS` is, in a single unscrolled frame,
**indistinguishable from an absent one.**

**Condition:** for each of the five tabs, either
- the frame shows the list's whole content (S27's rail absent, i.e. it does not scroll), **or**
- the tab is shot at top *and* at scroll-bottom, with S27's rail visible in both.

**Why it matters beyond tidiness:** without this, a "not present" verdict rests on absence of
evidence rather than evidence of absence — and this studio has a law about exactly that (`C37`).
I would have to return the set unadjudicated.

### 1.2 The corners sweat must contain the states whose absence is the question

*"Watched end to end"* is necessary and not sufficient. If the seed's match happens to produce a
quiet corners line, the set will show a flat sweat and **will not distinguish** *the theater has no
beats for this* from *this particular match had nothing to narrate.* Those are opposite findings
with the same-looking frames.

**Condition — the run must report its corner timeline** (count and minute per corner, and the leg's
line), whether or not the frames are interesting. With that, I can tell which of these occurred:

| state | why it is needed |
|---|---|
| the count approaching the line | §8A — is there any *approach* treatment at all |
| the count crossing it | §8B — the one genuinely terminal moment a count market has |
| **a leg decided with match time still to run** | §5 — the hand-over, which I argued is the bigger half |

**If the run produces none of the three, say so and the set is a null** — not a finding. Under `C37`
a null is only valid if success would have been resolvable, and a match that never approached its
line could not have shown an approach beat however the code behaves.

**Preferred, if the seed is choosable:** a ticket whose corners leg resolves *before* full time.
That single property exercises the crossing and the hand-over together.

## 2. PRE-COMMITTED READ — ENTRY's five tabs

### 2.1 The C19 question — binary

**PASS** = every one of the fifteen `MarketKind` members has a reachable home on ENTRY.
**FAIL** = one or more priced kinds has nowhere to be shown.

I expect FAIL on eight kinds. **Stating the expectation so that a PASS is the interesting result**,
not a relief — if they are all reachable, then either the tabs nest more than their labels suggest
or the engine is not offering what the enum enumerates, and **both of those are worth more than
being right.**

### 2.2 Density — direction of travel, deliberately not a number

The researcher's arithmetic said ~21 rows per screen and "not density-constrained." **I am not
carrying that number into the read.** Batch 95 is the standing lesson: a column's widest string is a
measurement, never something readable off type sizes, and this seat has been wrong twice this week
predicting instead of measuring.

What I commit to instead:
- **Direction:** the stale `s6-s8` frame showed six offers on `GOALS` with roughly half the body
  empty. I expect the current body to still have **substantial unused vertical space at the offer
  counts the tabs currently carry.** If it is *full or overflowing*, the whole premise of §5's
  presentation work changes and the phase re-plans.
- **Measured, not predicted:** row pitch, the market body's true top and bottom, the rendered
  product-fact size against the 13px floor, and whether any tab engages S27's rail today.

### 2.3 Structure — three things the stale frame asserted that must be re-confirmed post-migration

The `s6-s8` frame predates the TMP migration, so under `C43` it settles **nothing** about metrics.
It does suggest structure, and each of these is now a check:

1. Two-way markets render as an **over/under pair sharing one row** (matching every book).
2. A price sits in a **field with a rule beneath it**; the selected price takes the biro.
3. The tab rail is a **single level** — and it must stay one level. The research is unambiguous that
   the double-tiered rail is DraftKings' most criticised feature.

## 3. PRE-COMMITTED READ — the corners sweat

### 3.1 The premise check, stated as a falsifiable claim

The mandate's premise is *"a corners or cards bet settles correctly but watches flat."*

**CONFIRMED** = across the corners leg's live window, the surface's count-related output is limited
to reveal-tier chrome/audio with no accumulating, continuously-changing expression of distance-to-line
or time remaining.
**REFUTED** = there is already an accumulating or approach treatment, in which case §2's rate-line
proposal is an *improvement* to something rather than a *filling* of a gap — a materially different
spec, and a cheaper one.

**I hold the premise as probable and unmeasured.** It came from Allen, it matches what I read at
source, and it is still a claim about how something reads.

### 3.2 The hand-over question — the one I most expect to be told I have wrong

§5 argues a decided leg keeps being narrated while the match plays on, and that this is the bigger
half of "flat." **This is inferred from source, not seen.** The frames decide it, and the honest
outcomes are three, not two:

- decided legs **do** keep drawing narration → §5 stands and is the priority;
- the surface **already** moves to a live leg → §5 is withdrawn and §2 carries the phase alone;
- **no leg was decided early in this run** → neither, and the question rides to a later window
  rather than being answered by a set that could not see it.

### 3.3 What I will NOT conclude from this set

- Nothing about **cards**. This is a corners window. Booking drama (§3 of the exploration) is a
  separate surface question and a card set is not being shot — **named so its absence is not later
  read as "checked, nothing found."**
- Nothing about how a **rate line would read**, which needs a frame that does not exist yet.
- Nothing about **multi-leg** hand-over beyond what this one ticket's composition happens to show.

## 4. Why this document exists

So that when the frames dock, the read is executed rather than composed — and so that a set which
cannot answer its question is returned as a null instead of being made to yield one.

Both failures this pre-commitment guards against have happened in this studio inside the last
fortnight: `T99`'s first capture failed on its own condition and that was recorded as the most
valuable thing in the set, and `C51` was found only because someone was made to look at a place
nobody had reason to look.
